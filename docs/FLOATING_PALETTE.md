# Свободная палитра GenGate Studio

Studio сразу открывается отдельным системным окном. Заголовок перемещает его
обычным механизмом Windows, в том числе за пределы окна PhotoCraft и на другой
монитор. Кнопки отделения и отдельного режима для второго монитора нет.

Это то же состояние Studio в том же процессе и с той же сессией редактора:
промпты, референсы, задания и результаты не копируются между приложениями.
Крестик закрывает только Studio. Повторное открытие возвращает прежние условия.

Палитра принадлежит основному окну Windows: у неё нет отдельной кнопки на панели
задач, она остаётся над своим редактором и скрывается вместе с ним при
сворачивании. Глобальный always-on-top не используется. Когда редактор показывает
модальный диалог, палитра скрывается до закрытия диалога.

Сохраняются физическая позиция на рабочем столе и размер развёрнутого окна
в логических точках. Сворачивание в компактный заголовок не затирает размер
развёрнутого окна. При открытии проверяется доступность заголовка на подключённых
мониторах; потерянное за экраном окно возвращается на доступный монитор.
Геометрия записывается штатным хранилищем интерфейса `ui.ron`. Сохранённый размер
применяется при создании окна; дальнейшие изменения отправляются отдельными
командами, чтобы асинхронный ответ Windows не возвращал прежние габариты.

Custom, браузер LoRA и настройки LoRA рисуются в viewport Studio. Текстовый
ввод и буфер обмена обрабатываются в его контексте. Перенос слоя переводит
локальные координаты исходного окна в физические пиксели рабочего стола, затем
в точки целевого окна с его DPI. Файловый drop обрабатывается самим viewport
палитры, после чего используется прежний путь загрузки референсов.
При сворачивании браузер LoRA скрывается вместе с содержимым Studio и возвращается
при разворачивании. Общие уведомления об обновлениях остаются в основном окне
PhotoCraft; открытая палитра скрывается на время такого уведомления.

## Подготовка исходников

`scripts/prepare_palette.py` вызывается штатным `prepare_photocraft.py`. Он
копирует только eframe из уже закреплённого egui `6d518fc79968…` в
`.gengate-build/eframe` внутри подготовленных исходников. В копию добавляется
callback перед созданием дочернего окна. Он позволяет задать владельца
через безопасный `winit::WindowAttributesExtWindows::with_owner_window`.

Также путь отрисовки immediate viewport исполняет уже существующие команды
снимка экрана и буфера обмена так же, как основной viewport: в закреплённой
версии этот путь оставлял их в очереди. Остальная отрисовка не меняется.

Глобальный Cargo-кэш не изменяется. Версия/commit библиотеки сохраняются, обе
ссылки на eframe (crates.io и Git) разрешаются в одну локальную копию. Лицензии
копируются рядом. Новый unsafe-код и отдельная UI-библиотека не добавляются.
Изменения PhotoCraft и маленькая вставка в eframe воспроизводятся из шаблонов;
несовпадение ожидаемых точек интеграции останавливает подготовку.

Web и тесты со встроенными viewport продолжают использовать встроенное окно.
Специальная связь owner и восстановление монитора реализованы для Windows x64,
который является целевой платформой текущего пакета GenGate.

## Проверка без моделей

```powershell
.venv/Scripts/python.exe scripts/photocraft_palette_smoke.py --exe .runtime/palette-candidate/photocraft.exe --cli .runtime/palette-candidate/photocraft-cli.exe
```

Драйвер создаёт частный профиль и синтетический HTTP backend. Он управляет
палитрой через существующие Studio-команды официального MCP, без глобального
ввода мыши/клавиатуры и без загрузки моделей. Снимок дочернего viewport
запрашивается через `genstudio.studio.configure {palette:{capture:true}}`,
результат читается через `genstudio.studio.inspect {paletteCapture:true}`.
Очередь ввода, размеры, текст и память снимка ограничены; закрытие палитры
сбрасывает незавершённые запросы, сохраняя рабочие настройки.

Протокол для проверки конкретного окна принимает `positionPixels`, `size`
(логические точки), ограниченную последовательность `input` и `capture` внутри
`palette`. Он не является интерфейсом инъекции ввода в произвольные приложения.
Действия из этой очереди проходят ту же проверку разрешений команд, что и ввод
через основной MCP редактора. Бюджет снимка проверяется по физическим пикселям
до запроса чтения GPU, с учётом DPI.
Отчёт и снимки сохраняются в `.runtime/palette-smoke-*`.

Для ручного ревью используйте тот же запуск с `--interactive`. Редактор останется
открытым с отдельным профилем; Generate создаёт синтетические одноцветные
изображения. После закрытия редактора тестовый backend завершается. Установленный
PhotoCraft, пользовательские настройки, документы и модели не затрагиваются.

Подготовленный запуск для этого рабочего дерева:
`.runtime/release098-candidate/Review-Palette.cmd`. Это копия для ревью, не установщик.

## Первичная проверка на PhotoCraft 0.20.1

- 47 профильных UI-тестов: преобразование координат между viewport с разным DPI,
  перенос слоя без изменения исходного документа, сохранение геометрии,
  заполнение системной поверхности, доступность крестика длинного заголовка,
  маршрутизация вставки и ограничения запросов/памяти.
- Готовые exe через MCP: перемещение к `1200,120`, генерация синтетического
  результата, ввод кириллицы и Delete без удаления слоя, Neg, Seed, Custom 768×512,
  закрытие и повторное создание палитры с сохранением сессии.
- Сворачивание до заголовка 270×34 и возврат к 1000×700; сворачивание с открытым
  браузером LoRA, последующее раскрытие и сохранение его открытого состояния.
- Восстановление окна после недоступной позиции `-12000,-12000`; стабильный размер
  960×680 после изменения и после полного перезапуска редактора.
- Визуальная проверка тёмной/светлой темы, поля Seed, компактного заголовка и LoRA.
  Проверен также запуск через `pythonw` с частным профилем и чистое завершение
  тестового backend после закрытия редактора.

Отчёты: `.runtime/palette-validation.json`, `.runtime/palette-all-ui.json`,
`.runtime/palette-smoke.json`, `.runtime/palette-preview-check.json`.
Полный UI-набор: 4716 прошли, 21 ignored; приложение: 214 прошли, 3 ignored.
Clippy с `-D warnings`, зависимости 31 crate и WASM 24 crates + HEIF прошли.
Повторная подготовка/форматирование не изменяет 2259 проверенных исходных файлов.
Прежний Studio-драйвер адаптирован к дочернему viewport и повторно прошёл
референсы, batch/seed, Undo/Redo, `.pcraft`, 24 MP и отмену.
Реальные модели не загружались. Жест перетаскивания мышью между физическими
мониторами с разным масштабом остаётся пунктом ручного ревью: автоматически
проверены координаты, системное перемещение окна и восстановление геометрии.
