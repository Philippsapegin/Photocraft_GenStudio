# Аудит готовности GenGate к 0.10.0

Дата: 2026-11-03. Основа: GenGate 0.9.7, коммит `da4915d`, PhotoCraft 0.20.1, Windows x64.

Статус после исправлений: A01–A05 и согласованное поведение A06 изменены в рабочем дереве. Добавлен Custom-размер. Описание и проверки — в [материалах для ревью](REVIEW_AUDIT_FIXES.md). Ниже сохранены исходные результаты аудита версии 0.9.7.

Обновление 2026-11-08: реальные прогоны основных моделей и инструментов выполнены,
результаты пользователь принял как рабочие. FLUX3 проверена и через активный
пользовательский граф ComfyUI. Точная матрица, материалы и оставшиеся ограничения
(включая Constant LoRA) сохранены в [проверке моделей](MODEL_VALIDATION.md).
Утверждение об отсутствии реальной генерации ниже относится к исходному аудиту
2026-11-03, а не к текущему статусу разработки.

## Вывод

GenGate уже имеет содержательную основу для публичной версии: нативные инструменты, Studio, два движка, работу с масками, LoRA, негативным промптом, батчами и данными генерации в слоях. Однако пользовательский путь пока недостаточно устойчив. Есть подтверждённые ошибки повторной установки и обновления, неполное восстановление рецепта генерации и неявное переключение сценария Studio.

До 0.10.0 приоритет — надёжный первый запуск, обновление и повторение результата. Расширение списка моделей и провайдеров можно продолжить после этого.

## Что проверено

- Просмотрены установка, запуск, удаление, обновления, runtime, интерфейс Studio и передача данных генерации.
- Выполнены шесть сценариев на временных файлах с настоящими миниатюрными BSDIFF-патчами. Сбои загрузки и записи файлов внесены контролируемо; реальная сеть и GPU для них не нужны.
- Через настоящий редактор и официальный MCP выполнены три проверки Studio с синтетическим HTTP-движком: seed, следующая генерация после text-to-image, восстановление Direct-слоя при выбранном ComfyUI.
- Учтены проверки готового пакета 0.9.7: целостность ZIP, установка/обновление/восстановление/повторная установка, интерфейс Setup при 100%/150%, нативные и Python-тесты.
- Из пользовательской установки прочитан список версий: сохранено 11 каталогов программных версий. Ничего в них не удалялось.

Реальные модели не запускались, CUDA для генерации не инициализировалась, зависимости GPU Python не менялись. Пользовательские документы, профиль, модели и установленный редактор в ходе аудита не изменялись. Локальная среда — Windows 10; отдельного пользовательского прогона Windows 11 нет.

Локальные доказательства: `.runtime/audit010-probes.py` / `.json` и `.runtime/audit010-native.py` / `.json`. Пошаговые сценарии приведены ниже, чтобы выводы можно было проверить без этих локальных файлов.

## Подтверждённые ошибки

### A01 · P1 · После неудачной первой установки нельзя просто нажать Install ещё раз

**Сценарий:** первая установка Direct с новым runtime → сбой подготовки зависимостей → повторная установка в ту же папку.

**Получено:** в папке остаётся `versions/<version>-<id>`, но отсутствует `genstudio-install.json`. Повторный запуск считает эту папку посторонней и отказывает: `This folder already contains other files...`. В проверке исходный редактор остался нетронутым.

**Причина:** каталог версии создаётся до подготовки runtime, а распознавание существующей установки требует уже готового итогового metadata. Для незавершённой установки отдельного состояния нет.

**Код:** `packaging/installer.py:77`, `packaging/installer.py:203`, `packaging/installer.py:214`.

**Нужно:** отдельное распознаваемое состояние подготовки; повтор/продолжение или безопасная очистка принадлежащей Setup незавершённой версии. Сбои сети, pip, нехватка места и отмена должны приводить к понятному повторному запуску без ручного удаления папок.

**Приёмка:** прервать каждую стадию подготовки, запустить Setup в ту же папку, закончить установку. Посторонние файлы и модели не затрагиваются.

### A02 · P1 · Транзакция охватывает патч редактора, но не всю установку

**Сценарий:** после успешного применения патча возникает ошибка записи `Launch.ps1` в каталог GenGate.

**Первая установка:** редактор уже изменён, metadata установщика отсутствует, повторная установка блокируется как в A01.

**Обновление:** metadata продолжает указывать на старый runtime, а состояние редактора и настройки — на новый. Это воспроизведено. Журнала незавершённой транзакции уже нет, поскольку транзакция патча завершилась успешно. Проверка владельца при удалении может затем отказать из-за несовпадения runtime.

**Код:** `packaging/installer.py:261`–`266`, `genstudio/editor_patch.py:203`, `packaging/manage.py:22`.

**Нужно:** согласованный commit/rollback для файлов редактора, настроек, launcher и metadata установщика. Обновление должно оставлять либо предыдущую работоспособную установку, либо полностью новую.

**Приёмка:** внести ошибку записи на каждом этапе после подготовки, проверить согласованность всех указателей и возможность запуска, повторной установки и удаления.

### A03 · P1 · Обновление теряет часть настроек подключения

**Сценарий:** настроен ComfyUI на `http://127.0.0.1:8188` → обычное обновление через поля GUI.

**Получено:** адрес заменён на `http://127.0.0.1:8190`. Также сброшен сохранённый Python неактивного Direct-движка. GUI не передаёт `comfyUrl`, а backend собирает настройки заново и переносит только отдельные поля.

**Код:** `packaging/SetupWindow.ps1:159`, `packaging/installer.py:141`, `packaging/installer.py:216`.

**Нужно:** мигрировать полный валидированный набор настроек и заменять только явно изменённые пользователем поля. Разделить сохранённые конфигурации Direct и ComfyUI.

**Приёмка:** обновление с нестандартным портом, обоими Python, per-preset настройками, LoRA и workflow; при неизменённых полях конфигурация совпадает до/после, кроме нового пути GenGate runtime.

### A04 · P1 · Seed Direct теряется по пути к слою

**Сценарий:** генерация Direct → просмотр данных сгенерированного слоя.

**Получено:** синтетический backend получил seed `3537363148`, но в метаданных слоя `seed: null`. У следующей генерации seed другой; пользователь не может закрепить или восстановить первый через Studio.

В Python seed результата есть. При передаче в нативный редактор для preset-режима сохраняется только количество изображений, затем общий `Generation` создаётся с `seed: None`. Для ComfyUI seed уже проходит отдельным маршрутом.

**Код:** `genstudio/studio.py:129`, `genstudio/studio_edit.py:41`, `photocraft/genstudio_edit.rs:172`, `photocraft/genstudio_generate.rs:281`.

**Нужно:** передавать фактический seed каждого изображения в слой; добавить random/lock, копирование seed и повтор с тем же рецептом. Рецепт должен содержать фактические параметры, а не только текст промпта.

**Приёмка:** батч имеет отдельные seed в слоях; сохранение/открытие документа и восстановление в Studio сохраняют их. Повтор отправляет тот же seed и выбранные компоненты.

### A05 · P1 · Восстановление Direct-слоя не восстанавливает нужный движок

**Сценарий:** создать Direct-слой → переключить движок на ComfyUI → восстановить слой в Studio.

**Получено:** workflow-режим остаётся активным. В проверке Studio сообщает `model: workflow`, хотя восстановлен Direct-результат. Следующий Generate будет использовать активный ComfyUI-граф.

**Причина:** ветка восстановления workflow явно выбирает ComfyUI, а preset-ветка меняет только `studioMode` и модель. Выбранный ComfyUI по своей логике всегда включает workflow-режим.

**Код:** `photocraft/genstudio_canvas.rs:470`, `photocraft/genstudio.rs:169`.

**Нужно:** разделить действия «Использовать изображение/текст» и «Восстановить рецепт». Для полного восстановления сохранять и восстанавливать движок; для старых метаданных явно определить миграцию и поведение при недоступном движке. Текущее поведение подтверждено; требование восстановить движок следует из предлагаемого контракта полного рецепта.

**Приёмка:** переходы Direct → ComfyUI → восстановление Direct и обратный переход дают ожидаемый движок, prompt/negative, LoRA, размеры и seed.

## Незавершённые пользовательские сценарии

### A06 · P2 · Следующий Generate неявно становится редактированием

На пустой Studio первый Generate отправил 0 референсов. После завершения последний результат автоматически попал в основной слот. Второй Generate с тем же текстом отправил уже 1 референс. Это подтверждено через MCP.

Такое поведение может быть удобно для последовательного редактирования, но сейчас оно не оформлено как явный выбор. В батче автоматически берётся последний результат, а не обязательно тот, который пользователь считает лучшим.

**Предложение:** отдельное действие «Использовать результат как исходник» и явное состояние «Новая генерация / Редактирование исходника». Обычный повтор должен сохранять выбранный сценарий.

**Код:** `photocraft/genstudio_canvas.rs:424`, `photocraft/genstudio_canvas.rs:455`.

### A07 · P1 для публичного запуска · Первый успешный результат требует слишком много ручной подготовки

Новый пользователь выбирает папку моделей, устанавливает Direct, затем отдельно ищет и скачивает модель, encoder и VAE по таблице README. Setup может успешно закончить работу с пустой папкой моделей. Мастер до первого рабочего результата отсутствует.

**Минимум к 0.10.0:** выбрать preset → увидеть найденные и недостающие компоненты → получить точные ссылки/места установки → повторно проверить готовность. Проверять место и права записи до крупных загрузок. Сообщать требования выбранного runtime/GPU до первого падения; численные рекомендации памяти выпускать по результатам измерений.

Это можно сделать без автоматической загрузки всех моделей и без дополнительных провайдеров.

**Код:** `packaging/installer.py:126`, `packaging/installer.py:177`, `genstudio/models.py:46`; текущий пользовательский маршрут — `README.md`, раздел Installation / Model files.

### A08 · P2 · Обновляется пара PhotoCraft + GenGate, а интерфейс сообщает только о новой версии GenGate

Уведомление ведёт на общую страницу нового релиза и просит пользователя самому подобрать совместимую версию. Структура релиза содержит только номер и URL; версии поддерживаемого PhotoCraft в машинных данных нет. Возможна рекомендация нового GenGate пользователю с другой версией редактора.

Принятый путь с нативными патчами сохраняем. К 0.10.0 нужен понятный маршрут: текущая пара версий → доступная совместимая пара → порядок обновления → проверка/восстановление. Неизвестный редактор должен открываться обычным PhotoCraft с понятным следующим действием. Общий независимый API расширений — отдельная долгосрочная задача, а не условие этого выпуска; контракт PhotoCraft 0.20.1 по-прежнему описывает sandboxed WASM-фильтры.

**Код:** `photocraft/gengate_updates.rs:14`, `photocraft/gengate_updates_ui.rs:35`, `packaging/Launch.ps1`; контракт: pinned source `docs/plugins.md` PhotoCraft 0.20.1.

### A09 · P2 · Накопление версий и удаление требуют ручной работы

Каждый запуск Setup создаёт новый каталог версии, включая повторную установку той же версии. Автоматической очистки и интерфейса управления ими нет. В текущей локальной установке уже 11 таких каталогов.

Setup распознаёт собственный CUDA Python как «существующий» и может оставить новую версию зависимой от Python внутри старой. Поэтому просто удалить все старые каталоги нельзя. Uninstall корректно восстанавливает редактор, но сохраняет software, metadata и резервные копии; это скорее отключение, чем привычное полное удаление приложения. Повторная установка после восстановления в проверке работает.

**Нужно:** разделить принадлежащий GenGate GPU-runtime и версии host; учитывать зависимости при очистке, хранить последнюю рабочую версию и резервную копию. Дать явные действия «Восстановить», «Отключить», «Удалить программные файлы», с отдельным сохранением моделей и документов.

**Код:** `packaging/installer.py:203`, `packaging/SetupWindow.ps1:114`, `packaging/manage.py:24`, `packaging/Uninstall.ps1`.

### A10 · P2 · Состояния, ошибки и отмена пока слишком технические

В Setup есть пульсирующая полоса и журнал, но нет понятного плана стадий, оценки скачивания и действий восстановления. Cancel принудительно завершает дерево процесса; интерфейс обещает повтор, который ломается в A01. Во время короткой фазы commit нужна безопасная семантика отмены.

Ошибки движка в основном доходят как строки исключений/уведомления. Не хватает одной кнопки «Скопировать диагностику» и конкретного действия: указать недостающий файл, уменьшить размер, проверить подключение, повторить запуск. Диагностика для отправки должна исключать изображения и текст пользовательских промптов.

**Код:** `packaging/SetupUi.cs:257`, `packaging/SetupWindow.ps1:131`, `genstudio/direct_worker.py:104`, `genstudio/lifecycle.py:277`.

### A11 · P2 · Studio хранит текст черновика, но не весь его контекст

Prompt/negative, размер, batch и выбор LoRA сериализуются в `Workspace`; изображения референсов находятся в отдельном несериализуемом `Cache`. После перезапуска полноценный черновик не восстанавливается. Если текст содержит ссылки на изображения, он может остаться без соответствующих исходников.

Результаты сохраняются слоями, и это полезная основа. Но для workflow сохраняются путь/хеш, а активный граф имеет пустой путь; это не снимок графа для повторного запуска. История заданий host хранится в памяти и не заменяет историю Studio.

**Минимум:** сохранять согласованный черновик с референсами либо явно сообщать о временных исходниках и восстанавливать их из проекта; хранить полный рецепт. Полноценную отдельную галерею истории можно сделать позже.

**Код:** `photocraft/genstudio_canvas.rs:16`, `photocraft/genstudio_canvas.rs:64`, `photocraft/genstudio_workflow.rs:10`, `genstudio/studio.py:67`.

### A12 · P2 · Очевидные удобства Studio

В первую очередь нужны:

1. Компактный выбор/индикатор preset и движка в Studio, с переходом к компонентам. Сейчас смена preset спрятана в общих Preferences.
2. Seed/random/lock/повтор — вместе с исправлением A04.
3. Видимые возможности preset: требуется ли исходник, предел референсов, влияние negative, размеры. Кнопка Neg сама по себе не гарантирует влияние на результат у distilled CFG=1 моделей.
4. Явное действие «Использовать как исходник» и сохранение исходных референсов при повторе.
5. Управление размером, включая редактирование с исходником: сейчас в интерфейсе 1k/2k и предустановленные соотношения доступны для text-only. Точный размер и связь с холстом должны быть понятны пользователю.

Галерея с сравнением результатов, сохранённые prompt-шаблоны, избранные LoRA и дополнительные sampler controls полезны, но не должны вытеснять исправления установки и рецепта из ближайших двух выпусков.

**Код:** `photocraft/genstudio_ui.rs:471`, `photocraft/genstudio_canvas.rs:853`, `photocraft/genstudio_canvas.rs:879`, `genstudio/core_pipeline.py`.

## Что уже работает и стоит сохранить

- Проверки полного хеша редактора/CLI; неизвестная версия не подменяется старой.
- Транзакция изменений редактора, контроль резервных копий и восстановление после незавершённой транзакции.
- Shared models без обязательного дублирования; изоляция host и отдельного процесса генерации.
- Нативные слои/маски, один undo для импорта батча, positive/negative и LoRA в метаданных.
- ComfyUI получает свежий активный граф; overrides меняют только помеченные загрузчики в копии графа.
- Синтетические проверки действительно проходят через настоящий редактор, транспорт и файловые форматы.

Проблемы A01–A03 показывают границы этих гарантий: транзакция редактора и сохранение настроек не покрывают весь жизненный цикл Setup.

## Приёмка 0.10.0

### Установка и обслуживание

- Windows 11: чистая установка Direct с собственным runtime; установка с существующим совместимым Python; ComfyUI с обычным и нестандартным портом.
- Пустая папка моделей; нехватка места/прав записи; сетевой обрыв; отмена; повтор в ту же папку.
- Обновление предыдущего GenGate, повторная установка, переезд PhotoCraft, поддерживаемое и неподдерживаемое обновление редактора.
- Откат после ошибки, отключение/удаление и повторная установка. Проверка документов, настроек, моделей и внешнего Python до/после.
- Прогресс и итог Setup понятны без чтения полного журнала. Пакет проверяется из опубликованного ZIP.

### Работа

- Для каждого заявленного Direct preset: холодный старт, Studio, источник/референсы, batch, отмена, следующая успешная генерация; FIBO проверяется как edit-only.
- Ai Fill и Remove Brush: маска, граница холста, undo, повторный запуск; выделение AI проверяется отдельно.
- Сохранение/открытие проекта и восстановление полного рецепта; переходы между движками.
- ComfyUI: текущий несохранённый граф, несколько вкладок, отсутствующие IN/OUT, отдельные tool workflows и понятный путь исправления.
- UI в тёмной/светлой теме, на узком окне и при 100/150/200% масштабе; работа русской/английской раскладки.

Реальные GPU-прогоны требуют отдельного разрешения пользователя. Во время этого аудита они не выполнялись. Их цель — проверить первый реальный результат, отмену/восстановление, время старта и потребление памяти. Синтетические тесты остаются обязательными, но не подтверждают качество генерации и пригодность конкретной GPU-конфигурации.

### Документация и представление

- Один короткий маршрут «установить → получить первый результат → сохранить → обновить».
- Видимые совместимые версии PhotoCraft/GenGate, требования и ссылки на компоненты выбранного preset.
- Три законченных демонстрационных сценария: генерация/редактирование в Studio, Ai Fill, Remove Brush. AI selection — отдельная демонстрация после собственного прогона.
- Релизные тексты следуют `AGENTS.md`: пользовательские улучшения и исправления, без технического отчёта о переносе на новую версию PhotoCraft.

## Решение по объёму

К 0.10.0 стоит довести существующие режимы и сделать их предсказуемыми. Новые провайдеры, длинный список пресетов, глубокое управление ComfyUI и большой менеджер истории не нужны для первого уверенного представления продукта. Работающий первый запуск и восстанавливаемый результат важнее этих расширений.
